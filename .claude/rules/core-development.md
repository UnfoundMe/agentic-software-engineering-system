# Core Development Rules

## General

- Read relevant existing code before making changes.
- Understand the existing architecture before introducing new abstractions.
- Never modify unrelated files.
- Prefer the smallest change that correctly solves the problem.
- Do not silently change requirements.
- Do not invent missing requirements.
- If requirements are ambiguous, identify the ambiguity explicitly.
- Preserve existing behavior unless the task requires changing it.

## Before implementation

Always follow:

Investigate
→ Understand
→ Plan
→ Implement
→ Test
→ Validate
→ Review

## Completion

Never claim a task is complete without verification evidence.

Report:
- What changed
- Why it changed
- Files changed
- Tests executed
- Validation results
- Known limitations
